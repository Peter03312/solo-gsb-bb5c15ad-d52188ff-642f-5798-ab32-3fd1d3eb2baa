# 矩形纸张贯通式裁切排样（Paper Cutting Planner）

供小型印刷作坊使用的 Web 应用：输入母纸尺寸、刀缝、张数上限、搜索预算和
各类成品需求，自动搜索一份 **guillotine（贯通式）** 排样方案——每一刀都
贯穿当前正在处理的矩形余料，刀缝宽度被严格扣除，成品不重叠、不越界，并
遵守每类成品「能否旋转 90°」的限制。

输出：

- 每张母纸的逐张排样图（SVG，含成品名称、旋转标记、刀缝线）；
- 按实际执行顺序排列的贯通式裁切步骤（竖刀/横刀、坐标、刀长）；
- 各类成品的实际数量与需求对比。

找到任意可行方案即返回（不追求最优）。

## 一键启动（Docker Compose）

```bash
docker compose up --build -d
```

启动后浏览器访问：

```
http://localhost:8000
```

停止与查看日志：

```bash
docker compose down          # 停止（数据保留在命名卷 cutting-data 中）
docker compose logs -f       # 查看日志
docker compose down -v       # 停止并同时删除数据卷
```

镜像首次启动会自动创建 SQLite 表结构（幂等，可安全重复执行）。

## 本地直接运行（不用 Docker）

需要 Python 3.11+：

```bash
python -m pip install -r requirements.txt
python wsgi.py
# 开发模式（Flask 内置服务器，自动重载）：
FLASK_DEV=1 python wsgi.py
```

默认监听 `0.0.0.0:8000`，访问 http://localhost:8000 。

运行测试：

```bash
python tests/test_all.py
# 或 pytest（若已安装）
```

## 配置（环境变量）

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `PORT` | `8000` | HTTP 监听端口 |
| `CUTTING_DB` | `app/data/cutting.db` | SQLite 数据库文件路径 |

Compose 中把 `/app/data` 挂载为命名卷 `cutting-data`，容器重建后输入与
方案数据不丢失。改端口时同时修改 `docker-compose.yml` 的端口映射与
`PORT` 环境变量。

## 输入规则（非法输入返回 400，绝不写库）

- 母纸长、宽：正整数毫米，1–10000；
- 刀缝宽度：非负整数毫米，0–100；
- 张数上限、搜索状态数上限：正整数（分别 ≤ 10000、100000000）；
- 成品至少 1 种（最多 50 种）：长、宽为正整数，份数为正整数
  （≤1000000），「可旋转」必须是布尔值；
- 布尔值不接受数字伪装（`true` 不等于 1），尺寸不接受小数字符串。

## 搜索结果的三种状态（严格区分）

1. **找到可行方案 `found`**：满足全部份数，可查看排样图与裁切步骤并导出。
2. **已穷尽且无解 `infeasible`**：在给定母纸、刀缝、张数上限与旋转限制下
   完整搜索了整棵状态树，确认不存在可行方案。
3. **搜索预算耗尽 `budget`**：状态数达到「搜索状态数上限」时仍未确定。
   **此状态不表示无解**，界面明确提示可调大预算后重新排样；该状态不可导出。

搜索基于「角点放置 + 首刀归一化（竖切/横切）」的带记忆 DFS，显式枚举
成品分离与余料作废分支，因此在预算内完整遍历后给出的 `infeasible` 是
可信的；`budget` 仅是预算问题。

## 输入版本与方案失效

- 每次保存输入都会计算一份输入指纹（SHA-256，覆盖母纸、刀缝、张数上限、
  搜索上限和全部成品的尺寸/份数/旋转属性），界面与裁切单上显示为
  12 位「输入版本」。
- **保存方案后修改任何影响排样的输入，旧方案立即标记为失效**；此时导出
  裁切单会被拒绝（HTTP 409，`stale: true`），必须重新排样。
- 导出的裁切单（`导出裁切单` 按钮或 `GET /api/export`，纯文本 .txt）
  抬头标注输入版本号与完整指纹；仅当方案是对应最新输入的 `found` 方案时
  才允许导出。仅修改成品名称不改变版本（不影响排样）。

## 刀缝与坐标约定

- 坐标系原点在母纸左上角，X 向右、Y 向下，单位毫米。
- 裁切步骤中的坐标是**刀缝起点**，刀缝占据 `[坐标, 坐标+刀缝宽)`；
  竖刀沿 Y 方向贯穿当前余料，横刀沿 X 方向贯穿。
- 最后一刀切到外缘时，刀缝可越过纸边（边缘修切），越界部分为废边。

## HTTP 接口（可供脚本调用）

| 方法 | 路径 | 作用 |
|------|------|------|
| GET | `/` | 浏览器单页界面 |
| GET | `/api/state` | 当前输入、输入版本、方案及是否有效 |
| PUT | `/api/inputs` | 校验并保存输入（非法返回 400，不写库） |
| POST | `/api/solve` | 基于已保存输入运行搜索 |
| GET | `/api/export` | 下载裁切单（失效/非 found 方案返回 409） |

## 目录结构

```

  solver.py        guillotine 排样 DFS（found/infeasible/budget）

  db.py            SQLite 读写与失效判定

  templates/index.html  浏览器界面（排样图/步骤/数量）
wsgi.py            waitress 入口
tests/test_all.py  求解器与 Web 业务规则测试
Dockerfile, docker-compose.yml, requirements.txt
```
